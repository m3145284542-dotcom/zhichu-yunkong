# 智储云控工程接入与试点验收说明

本文件是后续现场试点的设计基线，不代表接口已经实现或设备已经接入。当前可交付能力是冻结实验的离线预测、储能调度、结果评价和 GUI 回放。DOEF v1.0、八建筑权重与既有科研证据保持冻结。

## 使用者与闭环

楼宇能源管理人员核对电池配置、审阅建议计划与异常记录，并决定是否授权执行；储能方案评估人员比较预测方法、削峰结果及失败案例；现场集成方负责电表、EMS、PCS/BMS 的协议适配与联调。项目提供预测和决策支持层，设备侧保留最终功率限制与保护权限。

智能电表/EMS 的历史负荷 → 智储云控预测 → 储能优化计划 → 经审批的 EMS/设备执行 → 实际负荷与执行回执 → 运行评价。当前前三步和事后评价在离线实验中完成；实时接入、审批、指令下发和设备回执尚未实现。GUI 只展示已保存的结果。

## 接口设计与输出

以下名称是建议的数据契约，不是现有 HTTP API。现有 `/api/demo` 是只读回放接口，不接收设备指令。首个试点可先通过文件交换实现影子运行，完成字段核对后再由集成方按实际设备协议开发适配器；本项目不声称支持任何特定厂商协议。

| 交换对象 | 建议字段与含义 | 接收后必须核对 |
| --- | --- | --- |
| 历史负荷 | building_id、meter_id、interval_start、interval_end、timezone、energy_kwh 或 average_power_kw、quality_flag、received_at | 明确区间起止、计量点与单位；拒绝重复、缺失、乱序和非有限值，不把缺失补零；电量除以区间小时数才是平均功率 |
| 设备状态 | battery_id、observed_at、soc_fraction、capacity_kwh、max_charge_kw、max_discharge_kw、available、alarm | SOC 比例与内部电量状态分别表示；状态新鲜度、可用容量、功率限制及设备告警 |
| 预测结果 | building_id、forecast_id、issued_at、data_cutoff、target_interval、load_kw、model_version、weight_version | 所有特征在截止时刻可得，覆盖完整目标区间，不复用其他建筑权重 |
| 建议计划 | plan_id、forecast_id、created_at、valid_from、valid_until、interval_start、charge_kw、discharge_kw、soc_kwh、predicted_grid_kw、solver_status | 两种功率均为非负且不同时充放电；计划有效期、SOC 轨迹、功率和日末约束；失败求解不得发布为有效计划 |
| 审批及回执 | plan_id、approval_status、approved_by、approved_at、execution_status、observed_at、actual_charge_kw、actual_discharge_kw、actual_soc、alarm | 审批与计划版本一致；重复计划幂等；过期拒绝；区分已接收、已执行、拒绝和执行偏差 |
| 评价记录 | plan_id、baseline_definition、actual_peak_kw、peak_reduction_rate、execution_error、constraint_events、data_coverage | 预计峰值与实际峰值分开；保留负削峰；实际无储能反事实须有可解释的计量/重建依据 |

当前电池优化输出的具体内部字段以 `src/battery/optimizer.py` 为准，上表是现场适配层契约，不能直接宣称已有此格式的导出器。离线科研指标见 `outputs/phase9/final_benchmark.csv`，逐建筑参数见 `outputs/phase7/building_battery_configs.csv`，冻结权重见 `outputs/phase8/selected_weights.csv`。

## 预测时点与现场 SOC

`src/features/load_features.py` 以时刻 t 的可用信息预测 t+24 h，各预测按目标日进入调度评价。它不是已经验收的“每天任意指定时刻一次性发布次日全天预测”服务。试点必须先约定计量区间何时结束、数据何时到达、预测截止时刻及发布时间，再证明每个目标小时的特征当时可得。缺失或延迟数据不得由事后数据回填后冒充实时预测。若发布时间改变导致原特征不可用，需要另立版本并独立验证，不能以现有测试结果背书。

当前仿真采用固定初始及终止 SOC 与每日重置。现场应使用计划启动时的实测 SOC，核对跨日连续性和设备可用容量，必要时另行设计终端约束或滚动更新。它们属于新控制协议，不能覆盖原实验配置，也不能承诺自动获得相同的削峰改善。

## 故障与回退设计

数据质量不合格、状态过期、设备告警或求解不可行时，将本次建议标为无效并记录原因，不沿用过期计划。通信超时、重复下发和回执缺失分别记录，禁止把“接口收到请求”当成“设备已执行”。现场安全状态由设备方与楼宇方在联调前明确；不能统一假定断电、零功率或继续旧计划在所有设备上都安全。设备保护、人工接管与紧急退出具有最高优先级。

## 分阶段验收

| 阶段 | 当前状态 | 进入下一阶段所需证据 |
| --- | --- | --- |
| 离线复现与回放 | 已实现，限冻结八建筑 | 科研哈希、指标一致性、仿真约束检查、GUI 来源校验；不能据此验收现场控制 |
| 只读影子运行 | 待实施 | 合法获得的现场数据；约定时间窗内的完整率和延迟记录；每小时特征可用性；计划/实际对照；无设备写入 |
| 人工审批试运行 | 待实施 | 接口联调记录；审批与计划版本绑定；实测 SOC 连续性；超时、重复、过期、告警、断联与人工接管演练；设备侧约束证明 |
| 受控自动运行 | 待实施 | 楼宇方与设备方签署验收；预先约定范围、监测窗口、指标阈值与退出条件；持续保留失败案例和执行回执 |

试点指标及阈值应在现场测试前约定，记录建筑、季节、测试窗口和基线，不能看到结果后更换成功标准。运行期峰值与执行偏差可直接监测；Oracle 后悔值需完整事后负荷和相同约束下的仿真比较。计费需需量计费规则，寿命需退化模型，碳减排需相应核算数据，均不由本次削峰率直接推出。

## 当前演示与答辩口径

运行 `python gui/server.py`，或打开便携 HTML。开始八建筑巡演，查看当前建筑每日峰值、运行总览和电池配置，暂停或切换下一栋，最后查看八建筑综合结果。GUI 的曲线是每日最大取电功率，不能读作逐小时充放电曲线。

建议开场：“假设明天下午办公楼会出现用电高峰，而电池容量有限，它应该几点放电？如果预测把峰值判断得过早，电量可能提前用完。我们因此同时评价预测误差和储能决策表现。智储云控目前完成了离线仿真决策支持闭环，现场应用将按影子运行、人工审批、受控执行逐步验证。”

答辩若问“现在能控制电池吗”，回答“当前展示冻结实验结果，尚未接入设备。报告给出了接入字段、责任分工和试点验收路径，设备控制仍需适配与联调。”若问“3.61%是什么收益”，回答“是固定八建筑平均归一化决策后悔值相对 LightGBM 的改善，不是节电率或电费收益。”
